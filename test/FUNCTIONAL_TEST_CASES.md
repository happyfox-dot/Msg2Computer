# Msg2Computer 功能测试用例

本文档用于评估当前双端功能开发是否有效。自动化测试覆盖纯逻辑模块；真实设备、系统权限、短信/通知/剪贴板等系统能力需要按下面的端到端用例验收。

## 自动化测试

在 Windows 端执行：

```powershell
cd desktop
npm test
```

覆盖范围：

- 消息权限策略：短信、普通短信、通知、剪贴板文本/图片/文件、文件传输的发送和接收开关。
- 软总线 envelope：旧协议消息和新 bus envelope 的双向转换。
- 路由计算：显示边和可路由边分离、无向 SPF、直连优先于 relay。
- 路由健康：失败直连临时降权，relay 可作为 fallback。
- 可靠投递：入站去重、出站 outbox、失败重试、ACK 后移除。
- 文件传输：manifest、分块拉取、sha256 校验、文件名消毒、可信环境明文块传输。

在 Android 端执行：

```powershell
cd android
$env:JAVA_HOME='C:\Program Files\Microsoft\jdk-17.0.19.10-hotspot'
.\gradlew.bat :app:testDebugUnitTest
```

覆盖范围：

- 短信验证码提取：英文 code/OTP 上下文、单候选兜底、日期/时间/弱验证码噪声过滤。

## 端到端功能验收

| ID | 场景 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- | --- |
| FT-01 | 新短信验证码事件触发推送 | Android 已授权短信权限；至少一个 Windows 节点可信且允许接收验证码 | 向手机发送一条新验证码短信 | Windows 弹出验证码通知；列表显示来源手机；同一短信不会重复显示 |
| FT-02 | 普通短信推送 | Android 打开“推送所有短信”；Windows 打开“接收全部短信” | 向手机发送一条非验证码短信 | Windows 显示原始短信内容；关闭接收开关后不再显示 |
| FT-03 | App 通知推送 | Android 已开启通知读取权限；允许推送通知 | 让任意第三方 App 产生一条新通知 | Windows 显示 App 名、标题/正文、来源设备；同一通知短时间重复刷新不会重复推送 |
| FT-04 | 剪贴板文本同步 | 双端可信；发送端打开文本剪贴板同步；接收端打开文本接收 | 在 Windows 复制一段新文本 | Android 剪贴板历史出现该文本；再次复制同一内容不循环刷屏 |
| FT-05 | 剪贴板图片同步 | 双端可信；图片剪贴板开关打开 | 在 Windows 复制一张图片 | Android 收到图片剪贴板记录；拓扑中其它节点不会反复回传同一图片 |
| FT-06 | 剪贴板文件同步 | 双端可信；文件剪贴板开关打开 | 在 Windows 复制一个文件 | Android 临时接收该文件；剪贴板更新为新文件时旧临时文件被清理 |
| FT-07 | 主动文件发送 | 双端可信；接收端允许文件传输 | Windows 文件传输页选择一个文件并指定接收节点 | 目标节点收到文件；历史记录显示保存路径；可打开/跳转目录 |
| FT-08 | TOTP 导入和重复覆盖 | Windows 上传/粘贴同一批 TOTP 二维码两次 | 第二次导入相同账号但参数不同 | 不产生重复条目；已有条目被更新 |
| FT-09 | TOTP 源端删除同步 | TOTP 由手机 A 提供并同步到 Windows/B 手机 | 手机 A 删除该 TOTP | 其它节点同步删除；非源节点本地删除只影响本机显示 |
| FT-10 | 拓扑可信入网 | A Windows 已有可信网络，B Android 未加入 | B 在 LAN 发现 A 并请求加入，A 确认 | B 成为可信节点；A/B 都能看到拓扑；未确认节点只显示发现，不进入路由 |
| FT-11 | 拓扑 gossip 自动扩展 | A、B 已可信，C 加入 B | C 入网后等待 gossip | A 自动看到 C；C 获得当前 LSDB 快照 |
| FT-12 | 可信域合并 | 两个可信小网络各有至少一个节点 | 一个节点手动确认另一个网络中的节点 | networkId 自动合并；全网逐步看到统一拓扑 |
| FT-13 | 端口状态一致性 | Windows 节点同时开放 WS 19527 和 relay 19529 | 查看拓扑页和文件传输目标列表 | 在线/可达状态一致；Windows 不被错误连接到 19529 WS |
| FT-14 | 后台频繁同步回归 | 手机熄屏并保持网络稳定 | 观察 5 分钟 logcat/桌面消息列表 | 无持续 topology_delta 风暴；无同一剪贴板/验证码反复显示 |
| FT-15 | 离线补发 | A 离线，B/C 发生拓扑变更和可靠业务消息 | A 重新上线 | A 通过 seenSeq/outbox 补齐必要变更；不重复消费已见消息 |

## 通过标准

- 自动化测试全部通过。
- 端到端用例中 P0/P1 场景无阻塞失败：FT-01、FT-03、FT-04、FT-05、FT-07、FT-10、FT-13、FT-14。
- 日志中不应出现持续增长的同一 `messageId`、同一 `topology_delta` 重复广播或同一剪贴板图片循环同步。
